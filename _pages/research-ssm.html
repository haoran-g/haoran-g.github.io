SSM
Secure Scattered Memory: High-Performance Memory Protection via Secret Sharing
Venue: Under Review — IEEE/ACM International Symposium on Microarchitecture (MICRO), 2026
Authors: Haoran Geng, Yuezhi Che, Dazhao Cheng, Michael Niemier, Xiaobo Sharon Hu
Background

Existing secure memory schemes face a fundamental tension between security and performance. AES-XTS (used in Intel SGXv2 and AMD SEV) lacks integrity and replay protection. AES-CTR with MAC and Merkle Trees provides full protection but incurs ~30% performance overhead from repeated counter (VN) updates and multi-level Merkle Tree traversals — requiring ~20 additional DRAM accesses per verification for a 32 GB secure memory. All existing optimization efforts (MorphCtr, EMCC, RMCC, COSMOS) still operate within the counter-based paradigm, accepting the fundamental separation between data and security metadata.

Design

SSM departs entirely from counter-based encryption, replacing it with polynomial-based secret sharing (Shamir's Secret Sharing). Each 64-byte data block is encoded into a degree-N polynomial whose coefficients are the data segments, plus coefficient seeds for integrity. K shares (evaluation points of the polynomial) are distributed across DRAM. On each read, t shares are fetched to reconstruct the polynomial via Lagrange interpolation, while d = K−t extra decoy shares obfuscate the access pattern. On each write, shares are regenerated and remapped to new physical locations, providing freshness without version numbers. An SSM page table (encrypted and cached in a 512-entry SSM TLB) maps logical blocks to share locations.

SSM achieves only 10% and 8% performance overhead vs. AES-XTS and AES-GCM respectively, while providing full replay protection. It outperforms MorphCtr by up to 40% and surpasses EMCC/RMCC by 12% and COSMOS by 3% on graph benchmarks. The SSM data processing unit occupies 0.27 mm² and consumes 284.53 mW at 28nm.

Conclusion

SSM shows that the counter-based encryption paradigm is not the only path to full memory protection. By replacing metadata with intrinsic share-based security, SSM achieves near-AES-XTS performance while delivering the complete confidentiality, integrity, and freshness guarantees of SGXv1-like schemes.
